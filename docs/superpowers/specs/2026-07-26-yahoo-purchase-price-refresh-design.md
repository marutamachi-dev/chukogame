# Yahoo!ショッピング購入価格更新設計

## 目的

楽天市場APIへの依存を終了し、国内Nintendo Switchパッケージ版300タイトルの購入価格をYahoo!ショッピングだけから毎日更新する。掲載する価格は当日取得・検証できたものだけとする。

## 採用ルール

- 対象はゲームマスターにある国内Nintendo Switchパッケージ版300タイトルだけ。
- Yahoo!ショッピングを購入価格の唯一の自動更新元にする。
- 各タイトルはまずJANで検索する。JAN検索で候補が得られない場合だけ、正式タイトル、続いて登録済み別名で検索する。
- 検索方法にかかわらず、採用する商品は応答のJANがゲームマスターのJANと完全一致するものだけ。
- 採用条件は中古、在庫あり、送料込み、正の価格、Switch 2ではないこと。
- 同日にYahoo!ショッピングで検証済み価格を得られなかったタイトルは、前回のYahoo価格と過去の楽天購入価格を公開データから除外する。
- 買取価格はこの変更の対象外とし、公式データ取得元が決まるまで新規更新しない。

## 更新フロー

1. GitHub Actionsの毎日ジョブが需要に応じた300タイトルを確定する。
2. Yahoo!ショッピングだけに対して300タイトルを更新する。
3. 各タイトルの検索結果をJAN、状態、在庫、送料、プラットフォームで検証する。
4. 対象タイトルについて、検証済みYahoo購入価格だけで既存の購入価格を置き換える。
5. 価格が取れなかったタイトルは購入価格なしとしてカタログを生成する。
6. 生成後のテスト、ビルド、コミット、Vercel本番確認を行う。

## 失敗時の扱い

- Yahoo API全体が失敗した場合は、既存データを維持してジョブを失敗扱いにする。
- 個別タイトルが検索0件または検証不一致の場合は失敗ではなく、当日の購入価格なしとして処理する。
- Yahoo APIの認証・障害・レート制限は明示的にログ集計し、推測価格を作らない。

## 検証

- JAN検索、タイトル再検索、別名再検索の順序をユニットテストする。
- JAN不一致、Switch 2、新品、在庫なし、送料別の商品を除外するテストを追加する。
- 当日Yahoo価格なしの場合に、過去のYahoo・楽天購入価格が残らないことをテストする。
- 300タイトル更新後に購入価格件数、価格未確認件数、API失敗数を確認する。
